The LibGodot fork inserts an optional window_id before use_filter so embedded
hosts can select the target window. This is an intentional fork API change;
source callers must pass the window ID before the filter or use named arguments.
The current five-argument API and generated bindings must remain unchanged.

Existing GDExtension binaries retain their four-argument bool filter through
RenderingServer's _compat_47 bindings, which forward to MAIN_WINDOW_ID.
Legacy hashes are 3759744527 and 2244367877 for set_boot_image, and 1104470771
for set_boot_image_with_stretch. Their argument types and defaults are covered
by the RenderingServer unit tests, in addition to the LibGodot API/C ABI checks.
The generic validator compares argument arrays before checking compatible hashes,
so it still reports these six structural differences. No other errors are allowed.
